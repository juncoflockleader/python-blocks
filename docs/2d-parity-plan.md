# 2D creation parity

Goal: reach practical 2D creation parity with mainstream children's block programming tools. The initial sprite module is a foundation, not completion of this goal. This checklist covers library behavior, creation tools and editor integration together. A Python method without usable blocks and authoring controls does not close a row.

**Current status: complete, verified 2026-10-07.** The [completion audit](2d-parity-audit.md) checks every D01–D13 requirement and representative-project gate against the final implementation. Final verification: 201 TypeScript tests, 110 native Python tests and 157 Chromium/Pyodide tests, with type checking and production build passing. The dated increment notes below preserve the implementation history; their next-step statements describe that earlier stage.

## Reference baseline

Use Scratch's storytelling/animation workflow and MakeCode Arcade's game workflow as complementary baselines, with the [feature survey](research/block-programming-feature-survey.md) supplying Code.org Game Lab, ScratchJr and Snap! comparisons. Preserve native Python semantics and the existing explicit cooperative async model; parity means learners can create comparable projects, not import Scratch projects or reproduce its language quirks.

Official sources checked on 2026-10-07:

- Scratch's [motion implementation](https://raw.githubusercontent.com/scratchfoundation/scratch-vm/develop/src/blocks/scratch3_motion.js) includes target movement, aiming, edge bounce and rotation styles. Its [looks implementation](https://raw.githubusercontent.com/scratchfoundation/scratch-vm/develop/src/blocks/scratch3_looks.js) covers dialogue, costumes, backdrops, effects and layering; [sensing implementation](https://raw.githubusercontent.com/scratchfoundation/scratch-vm/develop/src/blocks/scratch3_sensing.js) covers pointer/keyboard state, contact, distance, questions and timers. These are source references, not copied implementations.
- Arcade's [sprite reference](https://arcade.makecode.com/reference/sprites) establishes velocity, acceleration, projectiles, lifecycle events and effects. Its [scene reference](https://arcade.makecode.com/reference/scene) covers backgrounds, tile interactions and cameras; [controller reference](https://arcade.makecode.com/reference/controller) covers held buttons and controller-driven movement.
- Creation tools and debugging references remain linked in the survey: Scratch paint/sound tools, Game Lab's frame editor and watchers, and Arcade's tilemap/song editors.

This is a 2D module goal. Hardware, 3D, cloud accounts/galleries and whole-language text round-tripping remain separate product work. Sound and artwork tools, level placement and their workflows are included. The future AI helper remains assistance-only as specified in the [roadmap](roadmap.md#4-ai-agent-assist-mode).
